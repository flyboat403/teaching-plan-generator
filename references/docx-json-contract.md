# DOCX JSON 契约（generate_docx.py 输入）

> 仅在 Step 4 构造 DOCX JSON 时加载。版式参数见 `docx-style-spec.md`；本文件只定义 **JSON 形状**。
> 调用：`python3 scripts/generate_docx.py <input.json> [output.docx]`。**不要重写脚本**，只传 JSON。

## 顶层结构

```json
{
    "title": "《课程名称》「课题名称」教学设计",
    "basic_info": [
        ["课程名称", "办公软件应用"],
        ["课题名称", "文字环绕"],
        ["授课班级", "2025级计算机1班"],
        ["授课人数", "36"],
        ["学段", "中职一年级"],
        ["教育类型", "职业教育"],
        ["使用教材", "《Office 2019办公应用》"],
        ["教学课时", "1课时/40分钟"],
        ["授课类型", "实操技能课"]
    ],
    "sections": [],
    "output_path": "output.docx"
}
```

- `basic_info`：9 行 `[标签, 值]`，渲染为**无编号**信息表（4.0 / 11.0 cm）。
- `sections`：**12 个** Heading 1 章节对象（上例为空数组，实际须填满 12 节），顺序固定：

`一、学情分析` → `二、教学目标` → `三、教学方法` → `四、学习方法` → `五、教学重点及解决措施` → `六、教学难点及突破措施` → `七、教学资源` → `八、教学思路` → `九、教学流程` → `十、评价设计` → `十一、板书设计` → `十二、教学反思`

- MD 仍为 21 字段编号（十 学情分析 / 十一 教学目标）；DOCX = 信息表 + 上表 12 节。
- `output_path` 可省略（也可用第 2 个 argv）。旧版 `"fields"` 已废弃，脚本会报错。

## content 类型（`type` 可省略；与形状矛盾则报错）

| type | 形状 | 说明 |
|------|------|------|
| `text`（默认） | 字符串，或 `[{"text","bold","indent"}]` | `bold:true` 且未给 `indent` 时默认不缩进（知识目标等小标签） |
| `tables` | `[{header, rows, widths?, page_break_before?}]` 或单个该对象 | 多学时连堂 = 数组内多个流程表规格 |

## 表格行类型（`rows` 元素）

| 形状 | 含义 | 样式要点 |
|------|------|---------|
| `["单元格1", ...]` | 数据行 | 宋体 12pt 左、无底纹、不设垂直居中 |
| `{"band": "文案"}` | 分段带（学时/模块） | 整行合并，黑体 12pt 粗左、底纹 EDEDED、垂直居中 |
| `{"merged": "文案"}` | 缓冲/终局复盘 | 整行合并，按**数据行**样式（无底纹） |
| `{"cells":[...], "merges":[[i,j],...], "total":true}` | 合计行 | 按 ranges 合并，黑体 12pt 粗居中、底纹 E7E7E7 |

## 列宽 `widths`（cm，合计必须 = 15.0）

| 场景 | 默认 |
|------|------|
| 流程 4 列 | `[2.0, 6.4, 3.4, 3.2]` |
| 分层流程 5 列 | `[2.0, 5.6, 3.4, 2.6, 1.4]` |
| 评价 5 列 | `[2.2, 3.4, 5.4, 2.2, 1.8]` |

省略时按章节标题（含「流程」/「评价」）与列数自动取上表。`"page_break_before": true` 仅用于**第二学时**流程表首行分页。

## 教学流程表：每学时行结构

**行数关系**：下文「N 行」= 表格**总行数（含表头）**；JSON 的 `rows` **不含表头**（脚本 `add_table(rows=1+len(rows))` 自动加表头行）。

```
len(rows) = 表格总行数 − 1
```

**统一版（总行数默认 17 → `rows` 填 16 项）**：

```
表头 → 学时 band → 模块一 band → 3 数据行 → 缓冲 merged
→ 模块二 band → 3 数据行 → 缓冲 merged
→ 模块三 band → 3 数据行 → 终局复盘 merged
```

**分层版（模块三拆基础/进阶实操时总行数 = 18 → `rows` 填 17 项）**：模块三为 4 数据行（串联 + 基础实操 + 进阶实操 + 分层梳理）。其余模块也可按模板把核心授课拆为 2–6 行——**以所加载模板的表结构为准**，总行数不必锁死 17（`rows` 长度始终 = 总行数 − 1）。

- 时间列：`0-2min 导入锚定`（`min` 前无空格，半角连字符）；同一时段两行分层实操可共用 `28-34min 案例实操`。
- 缓冲/终局行写整段说明，不写短标签。

## 最小示例（教学流程 + 评价）

```json
{"heading": "九、教学流程", "type": "tables", "content": [
  {"header": ["时间/环节", "教师活动", "学生活动", "设计意图"],
   "widths": [2.0, 6.4, 3.4, 3.2],
   "rows": [
     {"band": "【第一学时 0—40分钟】1.1 文字环绕"},
     {"band": "第一模块：破冰筑基（0—10分钟）—— ..."},
     ["0-2min 导入锚定", "...", "...", "..."],
     {"merged": "第一次缓冲（10—13分钟）：随机提问，不讲新知识"},
     {"band": "第二模块：重难点攻坚（13—23分钟）—— ..."},
     ["13-15min 衔接与价值锚定", "...", "...", "..."],
     {"merged": "第二次缓冲（23—26分钟）：同桌互测，不讲新知识"},
     {"band": "第三模块：落地实操（26—36分钟）—— ..."},
     ["26-28min 知识串联", "...", "...", "..."],
     ["36-40min 终局复盘", "梳理核心＋布置课后任务＋留白答疑", "...", "..."]
   ]}
]},
{"heading": "十、评价设计", "type": "tables", "content": [
  {"header": ["评价维度", "评价指标", "评价标准（分值）", "评价主体", "评价方式"],
   "widths": [2.2, 3.4, 5.4, 2.2, 1.8],
   "rows": [
     ["学习态度", "...", "...", "教师/互评", "观察/记录"],
     {"cells": ["合计", "", "100分", "", ""], "merges": [[0, 1], [3, 4]], "total": true}
   ]}
]}
```

生成成功后**立即删除**临时 JSON（见 NEVER）。
